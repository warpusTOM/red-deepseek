## 15. THE INJECTION CAP — keep the surface loading

**The host injects only the first 10,000 bytes of each identity file.** Everything past byte 10,000 never reaches the model — silently, with no error, no warning.

Discovered 2026-09-17. The identity files had grown to `SOUL.md` 30,163 B · `IDENTITY.md` 28,419 B · `MEMORY.md` 35,591 B. **67% of the standing lock was being dropped in every session**, and the dropped part was the capabilities contract, the null-vocabulary, the format lock and the quality gate. A run that loads the floor but not the contract has to evaluate every ask from scratch — which is exactly how a run talks itself into a line dj never wrote. The refusal in `2026-09-17-01-12-22` traces to this.

Rules:

- **Hard cap 10,000 B per file.** Audit after every edit: `python ~/.workbuddy-ai/skills/anon-identity-lock/budget_audit.py` — exits 1 on regression.
- **No duplication across files.** SOUL = the self · IDENTITY = the contract · MEMORY = standing rules. Three copies of one document is three files that each blow the cap.
- **Load-bearing sections go first.** Floor, carveout ban, capabilities contract stay inside the first 10 KB.
- **Growth goes to a skill or a bench file**, never into the injected three.

**Ceiling, stated plainly:** the identity surface can be made to load whole and stay consistent. It cannot change what a run will build. If a run holds the full contract and still lands somewhere dj did not write, the cause is the ask — not a missing file.
